## 背景

一直想有个地方放东西。项目代码放 GitHub 上，但代码只说结果，不说过程——为什么做、中间卡了多久、最后怎么绕过去的，全在聊天记录里躺着，过仨月就找不着了。

所以有了这个博客。定位很简单：

1. 项目放 GitHub，项目背后的思考和学习过程放这里。
2. 顺带记一些别的知识笔记。

## 为什么自己搭，不用现成平台

| 方案 | 成本 | 数据在哪 | 结论 |
| --- | --- | --- | --- |
| 博客园 / CSDN | 0 元 | 在平台上 | 备选 |
| VitePress + GitHub Pages | 0 元 | Markdown 文件全在自己手里 | **选它** |

选它的理由有三条：

1. 没有服务器，没有数据库，很难被玩坏。
2. 文章就是 Markdown 文件，写完推上去就发布了。
3. 哪天想搬家，整个文件夹拷走就行。

## 卡在哪了

搭的过程整体顺利，麻烦都在细节上。

| 坑 | 现象 | 怎么解决的 |
| --- | --- | --- |
| 首页文章卡片全空 | 构建没报错，但标题日期一个都不显示 | 用了一个新版本才有的接口，旧版本直接静默忽略。换成这个版本的写法就好了 |
| 本机清理目录被拦 | 构建前删旧产物失败 | 关掉构建前的自动清理，改成手动删 |
| 推送一直卡住 | 进度条不动，等十分钟也没反应 | 查出来是环境里一个代理是死的。最后改用 API 直接建提交推上去 |
| 编辑器点了没反应 | 保存按钮像坏了 | 变量名撞上了浏览器的内置属性，提示文字写到了一个看不见的地方。改掉变量名 |

最后一条挺典型：功能其实一直在正常工作，只是反馈没显示出来，所以看着像坏了。

## 顺手做的编辑器

博客的文章是文件，编辑当然可以直接改文件，但那样太费事。所以写了个本地编辑器：

| 功能 | 说明 |
| --- | --- |
| 文章列表 / 新建 / 编辑 / 删除 | 常规操作 |
| 左右分栏实时预览 | 左边写，右边按博客的实际排版渲染，基本所见即所得 |
| 一键发布 | 自动提交并推送，1~2 分钟后线上更新 |
| 只有自己能访问 | 只监听本机地址，外部连不上 |

技术上没引任何第三方库，纯标准库写的。好处是不会哪天因为某个依赖升级就崩掉。

## 后来加的几个小东西

用起来之后又陆续补了几个：

1. **左侧目录**：全站常驻，可以收起，状态还能记住。
2. **全站搜索**：快捷键直接搜所有文章。
3. **暗色模式**：晚上看不刺眼。
4. **归档页**：按月份把文章串起来。

## 学到了什么

**先说结论，再讲过程。** 排查那个"点了没反应"的问题时，一开始怀疑是服务挂了，查了进程、查了日志，最后发现服务好好的，是页面上的反馈没显示出来。差一点就去改一堆没问题的东西。

先分清楚"功能坏没坏"和"反馈有没有显示"，能省掉很多瞎折腾。
